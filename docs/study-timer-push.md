# 집중·휴식 종료 알림

학생 화면의 오늘 수업 배너와 수업 시작 전 자동 푸시를 제거합니다. `class-reminder-check`는 이전 호출이 남아 있어도 발송하지 않는 종료된 엔드포인트로 유지합니다.

뽀모도로 타이머는 집중·휴식 종료마다 학생에게 푸시를 보냅니다. 기존 알림 권한과 FCM 토큰 등록을 사용합니다. 스톱워치는 종료 시각이 없으므로 예약 알림을 만들지 않습니다. 마지막 집중 회차 뒤에는 휴식이 없어 집중 완료만 알립니다.

## 서버 동작

- `study_sessions`의 INSERT/UPDATE 트리거가 `study_push_events`에 집중·휴식의 종료 시각을 저장합니다. 타이머 RPC와 공부 시간 계산 로직은 변경하지 않습니다.
- 집중 시작 때 휴식 종료 시각도 예약해, 브라우저가 닫혀도 두 알림을 처리합니다. 일시정지·중도 종료는 미래 예약을 취소하고 재개하면 남은 시간으로 다시 예약합니다.
- 세션·회차·단계마다 고유 이벤트를 두고, 이미 발송한 이벤트는 동기화해도 다시 예약하지 않습니다. 이벤트 테이블과 서버 발송 함수는 클라이언트 역할에 공개하지 않습니다.
- `pg_cron`이 10초마다 서버 발송 함수를 실행합니다(pg_cron 1.6 이상, pg_net 필요). pg_net으로 기존 `send-push`를 호출하며 대상 학생 ID는 서버 예약에서만 가져옵니다.
- 성공 응답을 확인한 뒤 완료 처리합니다. 실패는 최대 3회 시도하며 5분 넘게 지난 예약은 보내지 않습니다. 푸시 태그는 이벤트별로 고정해 재시도가 같은 알림을 교체하고 집중·휴식 알림은 구분되게 합니다.
- 새 예약은 새로 시작하거나 동기화한 타이머부터 생깁니다. 배포 전의 오래된 타이머를 일괄 발송하지 않습니다.

발송은 종료 후 다음 10초 점검에서 요청되며, 실제 수신 시각은 네트워크·브라우저·기기 알림 설정에 따라 달라질 수 있습니다. 푸시 본문에는 공부 목표 등 개인정보를 넣지 않습니다.

## 적용 순서

1. `send-push`, `class-reminder-check` Edge Function 배포
2. `study_timer_notifications_migration.sql` 적용 (`study_timer_migration.sql` 이후)
3. `study_timer_notifications_cron.sql` 적용 (수업 알림 cron 해제, 타이머 cron 등록)

`tests/study-push.test.mjs`는 HTTP 큐를 모형으로 대체한 PostgreSQL에서 예약, 취소, 재개, 화면 종료, 중복, 실패 재시도와 접근 권한을 검증합니다. 테스트에서 실제 학생에게 알림을 보내지 않습니다.
