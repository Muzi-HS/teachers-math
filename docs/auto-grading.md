# 자동채점 시험

## 운영 적용

1. Supabase SQL Editor에서 `supabase/auto_grading_migration.sql`을 실행합니다.
2. `supabase/auto_grading_cron.sql`을 실행합니다. `pg_cron` 활성화가 필요한 환경에서는 Database → Extensions에서 먼저 활성화합니다.
3. 서버 환경에 기존 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`가 설정되어 있는지 확인하고 앱을 배포합니다. 서비스 역할 키는 `NEXT_PUBLIC_` 변수로 노출하지 않습니다.
4. 테스트관리에서 시험을 만들어 학생 계정으로 한 번 응시해 보고, 제출 결과와 수업기록 자동입력을 확인합니다.

마이그레이션은 기존 시험을 모두 수동 방식으로 유지합니다. 자동채점 설정과 관련된 테이블/함수만 추가하며, 기존 성적은 바꾸지 않습니다. DB를 먼저 적용하고 앱을 배포합니다. 두 SQL 파일은 다시 실행할 수 있습니다.

## 사용

- 테스트관리 → 테스트 추가/편집 → **자동채점 사용**을 선택합니다.
- 각 문항의 배점과 정답을 입력합니다. ①~⑤를 누르면 객관식(복수 정답 가능), 빈칸에 입력하면 주관식으로 바뀝니다.
- 반을 누르면 현재 소속 학생이 선택됩니다. 개별 학생도 추가/제외할 수 있습니다. 저장 후 반 편성이 바뀌어도 이미 저장된 대상은 자동 변경되지 않습니다.
- **학생에게 시험 공개**를 선택하면 대상 학생의 **시험** 메뉴에 표시됩니다. 비공개로 바꾸면 새 응시는 막지만, 이미 시작한 학생은 계속 제출할 수 있습니다.
- 학생이 **답안 입력**을 누르고 시작을 확인한 시각부터 120초입니다. 새로고침이나 재접속으로 시간이 늘어나지 않습니다. 시험당 한 번만 응시할 수 있습니다.
- 학생 로그인 시 시험용 서버 세션을 발급합니다. 기존 자동 로그인 계정이나 세션 만료 시 시험 메뉴에서 학생 PIN을 다시 확인합니다. PIN을 5회 틀리면 5분간 대기합니다.
- 입력은 서버에 자동 저장됩니다. 직접 제출하거나 2분이 지나면 저장된 답안으로 채점됩니다. 네트워크가 끊긴 동안 서버에 도착하지 않은 답안은 마감 후 반영되지 않습니다.
- 앱을 종료해도 예약 작업이 마감된 응시를 채점합니다. 예약 작업은 1분 간격이므로 연결이 끊긴 학생의 결과는 마감 후 최대 약 1분 뒤 집계됩니다. **답안 수신 제한 자체는 정확히 120초**입니다.
- 시험 상세에 미응시/응시 중/제출 현황과 성적을 표시하고 10초마다 갱신합니다.
- 수업기록의 시험 선택 시 해당 학생의 저장된 정답 수·점수를 불러옵니다. 자동채점 시험은 읽기 전용이며, 저장 시 서버 성적을 다시 확인합니다. 미제출 시험에는 임의로 0점 성적을 생성하지 않습니다.
- 자동채점을 끄면 기존 수동 입력 방식을 사용합니다. 한 명이라도 응시를 시작한 시험은 정답·배점·대상·채점 방식을 바꿀 수 없습니다. 재시험이나 문항 변경은 새 시험을 만듭니다.

## 채점 기준

- 객관식: 선택 순서는 무관하며, 정답 집합과 정확하게 일치할 때만 해당 문항 배점을 받습니다. 일부 선택/추가 선택에는 부분 점수가 없습니다.
- 주관식: 앞뒤 공백을 제외한 문자열 일치입니다. `x = 2`와 `x=2`, `1/2`와 `0.5`는 서로 다릅니다. 수식의 동치 판정은 하지 않습니다.
- 배점: 문항당 1~1000의 정수, 최대 200문항입니다. 합계는 자유롭게 지정하며 기존 통계와 호환되도록 `획득 배점 / 전체 배점 × 100`을 반올림해 저장합니다. 정답 수와 실제 획득 배점도 보관합니다.
- 무응답은 오답이고, 0점은 빈칸으로 취급하지 않습니다.
- 채점 결과는 기존 `test_scores`에 저장되며 연결된 `record_test_items`에도 반영됩니다. 자동채점 성적의 직접 수정/삭제는 막고, 수동 시험의 기존 기능은 유지합니다.

## 검증

`npm test`는 임시 메모리 PostgreSQL(PGlite)에 실제 마이그레이션을 적용해 채점, 시간 제한, 중복 제출, 권한, 수업기록 동기화 등을 검증합니다. 운영 DB에는 접근하지 않습니다. `npm run build`로 타입 검사와 프로덕션 빌드를 확인합니다.

주의: 학생 계정의 기존 전화번호/PIN 저장 및 공개 정책 전체를 교체하는 작업은 포함하지 않습니다. 이번 시험 API는 서버에서 PIN을 재검증하고 서명된 HttpOnly 쿠키를 사용하며 정답표와 학생용 RPC의 직접 접근을 차단합니다.
